Tech Conference Program

A conference organizer curates a program track. Talks are first-class nodes — each linked to skills and speakers. The program is a profile; coverage checks which tracks have enough talks at the right level.

01 Ontology — talk nodes linked to skills, topics and speakers

A conference ontology mixes talk nodes (the program itself) with skill, topic and person (speaker) nodes. All in one graph — a talk is just another node.

ontology/talks/distributed-systems.yaml talk

Distributed Systems

Talk: "Consensus in production: Raft (Ongaro) vs Paxos (Lamport)". Level: senior. Links: skill:distributed-systems, speaker:alex-chen.

ontology/skills/platform-engineering.yaml skill

Platform Engineering

Internal developer platforms, golden paths, self-service infrastructure, DevOps culture.

ontology/topics/ml-systems.yaml topic

ML Systems

MLOps track: training, serving, monitoring, drift detection, feature stores.

ontology/people/alex-chen.yaml person

Alex Chen

Staff Engineer, ex-Google. Talks: distributed-systems, reliability-patterns. Skill: distributed-systems.

# ontology/talks/distributed-systems.yaml
id: distributed-systems

kind: talk

02 Program — tech-conference · main-track · threshold 0.7

The program selects talks and topics for a track. Talk coverage is weighted by required topic depth — a thin topic means the track lacks talks that cover it.

04 Export — conference-program.json

Everything derived is generated: a program package with talk abstracts, speaker profiles, and schedule — no hand-maintained spreadsheets.

{
  schemaVersion: "sdm.export.test/v1",
  profile: "tech-conference", level: "main-track", threshold: 0.7,
  talks: [ /* 21 talks · topic · speaker · level */ ],
  speakers: [ /* 15 speakers · bio · talks */ ],
  schedule: [ /* generated from talk nodes */ ]
}

Same specs generate other outputs: export mermaid for a program graph, export kit for track chairs, export matrix for topic coverage.
