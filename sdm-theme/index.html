Methodology · as specs · agent-first

Spec-Driven Methodology

SDM treats methodology as specs: written once, verified by machine, with all derived output generated automatically. Designed for the AI era — humans set the direction, AI agents execute the process.

agent-first — AI agent does the work, humans keep control
The problem

Methodology lives everywhere and nowhere

Before SDM, methodological artifacts are scattered across Wiki pages, Excel tables, LMS silos — with no single source of truth and no honest answer to "what is covered?".

Scattered matrices

Competency matrices in Wiki, Excel, LMS — different versions everywhere. Nobody knows which one is current.

No verifiable coverage

There is no reproducible answer to "what covers langchain4j for a Java Middle?". Coverage lives in the expert's head.

Assessment ≠ learning

Separate circuits: tests for hiring, courses for onboarding — no shared skill graph. Change a skill, update everything by hand.

AI makes it worse — and better

AI accelerates content production, but without a spec backbone you get more chaos faster. SDM gives AI agents a machine-readable skeleton to work within: humans define ontology and thresholds, agents compute coverage and generate exports. Quality = specs × agent × model.

The concept

What is SDM?

A single, machine-verifiable chain of methodological artifacts — independent of who performs the steps: a human or an agent.

ONTOLOGY

One graph

Nodes of any kind — skills, topics, concepts, talks — and their relationships in a single graph.

PROFILE

Selection & threshold

What is selected from the ontology and to what threshold. The profile defines the target.

COVERAGE

Fixed gap definition

What is missing, computed by a fixed measure. Identical across all implementations.

How it works

Lifecycle

Artifacts, not commands — the same chain, whoever runs it.

Ontology

A graph of nodes and relationships, any kinds.

Profile

Selection from the ontology with a threshold.

Coverage

Gap nodes by a fixed definition.

Export

The result goes to MCP, Obsidian, web, CLI, documents.

Architecture

Three layers

From specification to presentation — each layer has its own pace of change.

LayerWhatHow it changes
SpecificationOntology (nodes+kinds) + profile + gap definitionRarely
ComputationCoverage calculation by a fixed measureIteratively
PresentationExport (MCP / Obsidian / web / CLI / documents)Fully open
  1. Invariant. Given the same ontology and profile, the set of gap nodes is identical across all implementations. The gap definition is fixed by the methodology — implementations do not choose it.
AI-native

Agent-first: humans on intent, AI on execution

SDM is built for the AI era from the ground up. Humans describe what they need — AI agents do the heavy lifting within spec boundaries.

Human says intent

"I need a Java Middle profile with AI/LLM skills." The agent clarifies, shows a plan, waits for confirmation. No CLI flags. No YAML by hand.

Agent executes

Agent calls SDM via CLI/MCP: creates skills, adds questions, computes coverage, exports artifacts. Stays within frame — can't violate invariants.

You review the result

Coverage report, export preview — you say "ok" or "fix this". The agent iterates. You stay in control, the agent does the work.

The loop continues

Agent suggests next steps: close gaps, harden quality, export for a new surface. Same frame, guided by methodology state.

Intent · Spec-Driven Methodology · Agent

Human → Agent + LLM → CLI / MCP / skills → SDM → Specs YAML

Quality = specs × agent × model. The methodology constrains the agent — it does not choose the gap definition, does not bypass validation.

Boundaries

What it is not

Clear boundaries help keep the methodology focused.

Not SDD (that is about code)
Not a tool/product — CLI, MCP, plugins are implementations
Not a storage format (YAML is not required)
Not an LMS or testing platform
Not a judge — content quality checks are outside
Not about questions only — profile elements can be anything
Audience

Who is it for

Methodologists, educators, teachers, bloggers, conference organizers — anyone who works with methodological artifacts and wants to verify their completeness.
